# M5: explicit scoped reflection and configuration updates

This records the M5 boundary. [M6](m6.md) now adds logger/injection/type/example
acceptance and the final compatibility audit.

M5 implements Rust equivalents of isolated/traced service access, reflection,
internal hooks, and configuration convergence. It preserves M4's `Rc<T>` reads
and exact-publication cleanup; it does not transparently rewrite Rust methods.
The workspace remains local, non-Send, Rust 2024 with a tested 1.85 minimum.

## Scope and bound calls

`IsolationId::new()` creates a shareable slot identity. `ctx.isolate(&key)`
creates a fresh boundary; `isolate_with(&key, &label)` selects a shared slot.
Even the same label creates a new boundary stopping inherited injection rights.
No isolated slot falls back to an ancestor slot. Equal Rust types, names,
values, and labels with equal descriptions do not collapse identities.

Publications retain their exact slot and definition Context. Committed bindings
retain both the requested name and exact publication, including checked
cross-name shared-slot aliases. Context ancestry retains boundary history,
not just a flattened final map. M4 cleanup waits still include withdrawn
publications and Registry-removed consumers.

`ctx.bind(&key)` returns `BoundService<T>`; `bind_direct` bypasses injection
authority but requires an available provider. `bound.call(|service, ctx| ...)`
passes the explicit traced Context. Its checked lookups use the provider's
definition while metadata, realm selection, intercept layers, plugin creation,
and effects use the caller's use site. Root calls cannot grant a plugin-defined
method root dependency authority. `definition_site`, `use_site`, and `caller`
make these separate views inspectable.

`map` extends a service/holder without losing its definition. `rebind` retraces
a captured holder at another use site, never nesting shadows or crossing runtimes.
`call_unshadowed` explicitly passes the unshadowed use Context and caller,
replacing noShadow tracking. `ServiceInvoke<A>` plus `bound.invoke(args)` replaces
callable objects. New child plugins discard the service shadow and inherit the
use-site owner/scope.

`Dependency::with_config(C)` supplies typed injection config. `ctx.intercept`
adds use-site layers. `bound.intercepts::<C>()` returns nearest admitting
injection config first, then outer-to-inner Context layers; own provisions do
not borrow injection config. `resolve_intercept` accepts the service-specific
merge operation, including non-shallow/custom merges. Incompatible config types
return checked errors. `bound.dispatch_options()` / `ctx.service_filter(&key)`
filter every event mode by use-site realm; global listeners still bypass filters.

## Explicit reflection

`AccessorKey<R,T>` selects a global accessor contract including receiver type.
`ctx.accessor(key, Accessor::new(get).with_setter(set))` registers Fiber-owned
cleanup. `read_accessor`/`write_accessor` preserve the explicit receiver and
accessing authority. Readonly, missing, duplicate, and incompatible contracts
are errors. Service property declarations persist as in TS; accessor declarations
are removed with their effect.

`Accessor::from_service` is the typed mixin adapter. `BoundService::associated`
uses a dotted service name with the original accessing code's authority.
Bound accessor methods likewise retain that authority rather than borrowing
the base service's own inject rights. Ordinary Rust methods, structs, and
interior mutability replace arbitrary prototype/property mutation.

## Updates and hooks

`fiber.update(source)` starts work now and returns a wait-only `LifecycleTask`.
`update_with(source, UpdateOptions { no_save: true })` suppresses only
`internal/commit`, not source replacement or middleware.

Loaded candidates are synchronously transformed/validated before source commit,
error reset, or update middleware. An invalid candidate leaves the old source
and resources running. Pending candidates retain only the latest source and
validate when dependencies become available. `ValidationError` retains typed
`ValidationIssue` paths (`PathSegment::Key/Index`), while arbitrary typed
validator errors remain supported.

`ctx.on_update` registers local async-around middleware receiving `Rc<R>` of
resolved config and an owned one-use continuation. Calling next starts restart;
omitting it accepts the new source without restarting, including during Loading.
`on_update_sync` is the eager-prefix adapter: true continues, false accepts.
Local hooks are scoped effects removed on reload/manual removal; ordinary
global hooks run after the local router, prepended globals before it.

Update/restart revisions and exact dependencies form one target. In-flight
cleanup finishes before the latest target loads; intermediate configs may be
skipped. ABA/equal-final-config updates still force a new load. Obsolete failures
are diagnosed without poisoning the latest target. Update clears a failed Fiber
and can await successful/failed asynchronous recovery. All waiting updates
observe the latest load failure, which is diagnosed once even if waiters drop.
Terminal disposal wins over queued update/restart intent.

Effect streams owned by an invalidated load stop before their next advancement,
but retain the already-in-flight final acquisition and its disposer. No native
future is forcibly aborted. Acquisitions and providers remain retained through
rollback and child cleanup as in M4.

`hooks` exposes typed events for plugin/status/service/commit observations,
config/get/set around-middleware, listener replacement, and dispatch observation.
`Value::get<T>` checks heterogeneous payload contracts. Listener interception
can replace a typed callback/options without recursively intercepting itself.
Non-internal dispatch notifications include mode, exact typed event (including
symbol identity), arguments, and use Context. Built-in protocols are methods,
not root-owned listeners that disappear on root drain.

Pending/Failed disposal goes directly to Disposed; active disposal reports
Active -> Unloading -> Disposed. These sequences are now tested as hook events,
not inferred from state snapshots.

## Deliberate representations and safety deviations

- Existing `get`/direct `Rc<T>` reads do not trace arbitrary methods. Use bound
  adapters for traced behavior. Dynamic Proxy property access, constructors,
  decorators, arbitrary receiver mutation, and implicit return-value tracing
  are replaced by explicit typed operations.
- Synchronous get hooks can run without host admission, preserving M4's pure
  read surface. New registrations/async dispatch still require the host.
- Observer failures are diagnosed and retained without stranding cleanup.
  Config/update middleware failures still reach their operation's caller.
- Shared-slot alias notifications also refresh aliases selecting that slot,
  avoiding the teardown deadlock possible with name-only notifications.
- Schema integration is synchronous Rust validation, not automatic discovery
  of Standard Schema objects or async validators.

## Evidence

At this boundary there are **128 integration tests** and **ten Rustdoc checks**.
New suites are `tests/scoping.rs` (8), `tests/updates.rs` (16), and `tests/hooks.rs`
(4). They cover boundary history, checked aliases, nested definition/use views,
intercept precedence, receiver/accessor contracts, callable extensions, both
previously deferred realm-retention declarations, update races/recovery,
middleware ordering/removal, source/resolved validation, noSave, exact status
sequences, typed hook interception, and outdated stream advancement.

The pinned checklist remains case-level evidence, not a claim of identical
JavaScript syntax. M6 owns final logging, injection adapters, compile-time API
checks, the end-to-end example, and the parity/deviation review.

The final [M6 verification](m6.md#verification) supplements the original
label-based runs with explicitly selected compiler, Cargo, Clippy and Rustdoc
binaries and isolated target directories. It reruns all M5 contracts on actual
Rust 1.85.0 and stable 1.97.1; a label/version probe alone was insufficient in
this mixed Homebrew/rustup environment.
